# Theming

A theme gives an instance its look and its words: name, colors, fonts, icons, logo and, if you want, changed page text.
It never changes the JavaScript. The same two scripts run on every instance, whatever it looks like, which is what lets
[`bun run verify`](threat-model.md#what-bun-run-verify-checks) compare any deployment with this repository.

The default theme is in `themes/default`: system fonts, an indigo palette, rounded corners and
[Lucide](https://lucide.dev) icons (ISC license, see `themes/default/ICONS-LICENSE`). Copy that folder as a starting
point.

## Using a theme

```bash
VK_THEME=/path/to/my-theme bun run build
VK_THEME=/path/to/my-theme VK_ORIGIN=https://secret.example.com bun run deploy
```

`VK_THEME` is a directory. The build imports `<dir>/theme.ts` and expects a default export that is a `Theme`. It fails
with "does not export a complete Theme" if `config.origin` or `stylesheet` is missing. The theme can live outside this
repository (the hosted instance's theme does).

A theme is TypeScript that Bun executes during the build, with your privileges. Use only themes you have read.

## What a theme controls

The page structure is generated by `site/build.ts`, and the text by `site/copy.ts`. A theme supplies:

| Field | Purpose |
|---|---|
| `config` | Origin, product name, repository, contact, optional operator and header link |
| `stylesheet` | Colors, type, spacing, shapes: loaded after `site/base.css` |
| `files`, `head`, `ogImage`, `themeColor` | Extra files, extra `<head>` tags, social image, browser color |
| `icon()`, `glyph()`, `logo()`, `divider()` | The artwork, as inline SVG or HTML strings |
| `cta` | An optional promotional section above the footer |
| `copy()` | A function that can change any page text |

## The `Theme` interface, field by field

The definition is `site/theme.ts`.

```ts
interface Theme {
  id: string;
  config: SiteConfig;
  stylesheet: string;
  files?: Record<string, string>;
  head?: string;
  ogImage?: Record<Lang, string>;
  themeColor?: string;
  icon(name: IconName, size: number): string;
  glyph(name: GlyphName): string;
  logo(): string;
  divider(): string;
  cta?: Record<Lang, { h2: string; text: string; button: string; href: string }>;
  copy?: (lang: Lang, copy: Copy) => Copy;
}
```

`Lang` is `"lt" | "en"`. Both languages are always built.

### `id`

A short name. It appears in the build log and as a comment (`/* theme: <id> */`) in the bundled stylesheet.

### `config`

| Field | Meaning |
|---|---|
| `origin` | Canonical origin, no trailing slash, for example `https://secret.example.com`. Required. Used in canonical and hreflang links, Open Graph tags, the sitemap, `llms.txt` and the JSON-LD |
| `product` | Product name in the header, page titles, `og:site_name`, structured data and the abuse-report subject. A string, or `{ lt: "…", en: "…" }` for a different name per language |
| `repoUrl` | Public source repository. Linked from the footer and from the commit name (`<repoUrl>/tree/<commit>`) |
| `publicSource` | Optional, default `true`. `false` (for example while the repository is private) leaves out everything that links to `repoUrl` or calls the code open source: the footer source link and the link on the version, the "open source" footer line, the FAQ answer about checking the code with `bun run verify`, the open-source sentence in the meta description, the hero label and the price answer, the license in the structured data, and the source line in `llms.txt`. The header gets no default button. Pages still carry `vk-version` and `vk-commit`, so `bun run verify` keeps working. A theme that overrides these strings has to remove the claims from its own copy too |
| `contactEmail` | Where abuse reports and questions go. Shown in the footer and the FAQ |
| `operator` | Optional. `{ name, url: { lt, en } }`: who runs the instance. Shown after "Made by" in the footer (Lithuanian: "Sukūrė") and used in the JSON-LD. Without it the footer says "Open source project, MIT license" |
| `headerLink` | Optional. `{ label: { lt, en }, href: { lt, en } }`: the button in the header. Defaults to the source code link |

### `stylesheet`

An absolute path to a CSS file. The build concatenates `site/base.css` and then this file into one content-hashed file
under `assets/`, referenced with a Subresource Integrity value. `base.css` handles layout and components and takes all
colors, fonts and the radius from the tokens below, so a theme can be little more than a token file. It can also add or
override any rule.

### `files`

Extra files to publish: a map from the published path to an absolute source path.

```ts
files: {
  "/favicon.svg": join(import.meta.dir, "favicon.svg"),
  "/fonts/body.woff2": join(import.meta.dir, "body.woff2"),
}
```

Every page links `/favicon.svg`, so provide one. Fonts must come from your own origin: the CSP allows `font-src 'self'`
only, so a font service such as Google Fonts is blocked. Declare them with `@font-face` in the stylesheet.

### `head`

A string of extra tags for `<head>`, placed before the stylesheet. Useful for font preloads:

```ts
head: `<link rel="preload" href="/fonts/body.woff2" as="font" type="font/woff2" crossorigin>`,
```

Do not put `<script>` or `<style>` blocks here. The CSP blocks inline ones, and the verification would not cover them.

### `ogImage`

Social preview images per language, as published paths, for example `{ lt: "/og-lt.png", en: "/og-en.png" }`. They are
declared as 1200 by 630 pixels, and you add the files through `files`. Start the file names with `og-`: the generated
`_headers` file gives only paths matching `/og-*` a cross-origin resource policy, so that social crawlers can fetch them.
Without `ogImage` the pages use the plain `summary` Twitter card.

### `themeColor`

The browser UI color (`<meta name="theme-color">`). Default `#111827`.

### `icon(name, size)`

Returns the HTML for one icon. Rules:

- The outer element must carry the class `icon`. `base.css` hooks `.icon` (for example `.step-icon .icon`, `.card .icon`,
  `.faq .icon`).
- The default theme wraps a Lucide SVG in `<span class="icon icon-badge icon--48">` and sizes it with classes (see
  the rules below about inline styles).
- Mark decorative SVGs `aria-hidden="true" focusable="false"`; the labels are in the surrounding text.

Names the type requires: `key`, `server`, `eye`, `inbox`, `shield`, `calendar`, `flag`, `stamp`, `bank`, `database`,
`clipboard`, `plug`, `lifebuoy`, `code`. The built-in pages use all of them except `code`; the core copy chooses most of
the icons by name. Sizes requested by the built-in pages are 24, 40, 44, 48 and 56.

### `glyph(name)`

Returns a small interface glyph. The names are `check`, `cross`, `plus`, `theme` and `chevron`.

- The element must carry the classes `glyph glyph-<name>`, for example `glyph glyph-chevron`. `base.css` sizes
  `.glyph-chevron`, `.glyph-check`, `.glyph-cross`, `.glyph-plus` and `.glyph-theme`.
- The build also renders every glyph into a `<template id="glyph-<name>">` at the end of the page. The shared script
  clones `glyph-chevron` into the buttons it creates, which is how the script stays free of theme artwork.

### `logo()`

The mark shown next to the product name in the header and in the footer. It is inserted twice per page.

### `divider()`

A decorative divider used in the header, between sections and in the footer. Return `""` for none.

### `cta`

Optional. When set, a section is added above the footer on the home page, per language:
`{ h2, text, button, href }`. It is meant for the operator's own offer or link.

### `copy(lang, copy)`

Called once per language with the core copy built from `config`. Return the changed copy. The `Copy` type is defined by
the object in `site/copy.ts`; the part named `ui` is shipped to the browser as JSON for the interactive parts.

```ts
copy: (lang, copy) => ({
  ...copy,
  hero: { ...copy.hero, label: lang === "en" ? "Internal tool" : "Vidinis įrankis" },
}),
```

Keep the text true. The core copy states what the code does (for example "no cookies", "deleted after the first read");
if your deployment differs from that, for example because you turned on request logging, say so. The core answer to
"What do you store about me?" also says that the service counts how many links are created, answered and opened each day, as
totals ([daily totals](self-hosting.md#daily-totals)); if you replace that answer, keep that sentence.

## Tokens

`site/base.css` lists the tokens a theme is expected to define. Define them for `:root, .light-scope` (light values) and
override the page tokens for `:root[data-theme="dark"]`.

| Group | Tokens |
|---|---|
| Palette | `--ink` `--ink-soft` `--paper` `--mist` `--rule` `--muted` `--link` `--accent` `--tint` `--tint-alt` `--dot` `--shadow` `--highlight` `--highlight-soft` `--danger` `--ok` `--ok-soft` `--ok-bg` `--ok-ink` `--warn-bg` `--warn-ink` `--error-bg` `--error-ink` `--cross` `--dark-bg` `--dark-muted` `--dark-rule` `--cta-bg` `--cta-ink` |
| Shape and type | `--radius` `--font-sans` `--font-display` `--font-mono` |
| Page tokens (light and dark) | `--page-background` `--panel-background` `--border-color` `--text-color` `--text-muted` `--link-color` `--button-background` `--button-foreground` |

`base.css` also declares layout variables on `:root` that a theme may override: `--container-width`, `--page-gutter`,
`--header-height`, `--pad` and `--ease-in-out`.

Light and dark mode: a small script sets `data-theme="light"` or `"dark"` on `<html>` from the stored choice or the
system setting. Areas with the class `light-scope` (the tool card, the app card, the illustrations) keep the light values
in both modes, which is why the first selector in the example below includes `.light-scope`.

## A minimal theme

`themes/example/theme.ts`:

```ts
import { join } from "node:path";
import type { Theme } from "../../site/theme";

const svg = (className: string, body: string) =>
  `<svg class="${className}" viewBox="0 0 24 24" width="16" height="16" fill="none" stroke="currentColor" stroke-width="2" aria-hidden="true" focusable="false">${body}</svg>`;

const GLYPHS = {
  check: '<path d="M20 6 9 17l-5-5"/>',
  cross: '<path d="M18 6 6 18M6 6l12 12"/>',
  plus: '<path d="M12 5v14M5 12h14"/>',
  theme: '<circle cx="12" cy="12" r="4"/>',
  chevron: '<path d="m9 18 6-6-6-6"/>',
};

const theme: Theme = {
  id: "example",
  config: {
    origin: process.env.VK_ORIGIN ?? "https://secret.example.com",
    product: "Example secrets",
    repoUrl: "https://github.com/areza-digital/one-time-secret-link",
    contactEmail: process.env.VK_CONTACT ?? "abuse@example.com",
  },
  stylesheet: join(import.meta.dir, "theme.css"),
  files: { "/favicon.svg": join(import.meta.dir, "favicon.svg") },
  themeColor: "#0f766e",
  icon: (name, size) => `<span class="icon icon--${size}">${svg("icon-svg", `<circle cx="12" cy="12" r="9"/>`)}</span>`,
  glyph: (name) => svg(`glyph glyph-${name}`, GLYPHS[name]),
  logo: () => `<span class="logo-mark">${svg("logo-svg", GLYPHS.check)}</span>`,
  divider: () => "",
};

export default theme;
```

This is the least a theme needs: the example draws every icon as the same circle, so a real theme should map each icon
name to its own artwork, as `themes/default/theme.ts` does. Try it with `VK_THEME=themes/example bun run dev`
(or `bun run build` to write `dist/`), and check both languages, both color modes and a phone width.
`bun run scripts/shoot.ts` takes screenshots and reports horizontal overflow.

## Rules

These follow from the Content-Security-Policy (`default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'
data:; font-src 'self'; connect-src 'self'`) and from the verification guarantee.

1. **The JavaScript must not change.** A theme must not add scripts, and the pages must not depend on theme code at
   run time. The scripts are built from `src/web/` and do not read theme files.
2. **No inline styles and no inline scripts.** `style-src 'self'` blocks `style="..."` attributes and `<style>`
   elements, in SVG too. Use classes and the theme stylesheet. Sizes in the default theme are classes
   (`icon--24` to `icon--56`) for this reason. Event-handler attributes such as `onclick` are blocked as well.
3. **No third-party resources.** Fonts, images and stylesheets must be served from your origin (use `files`), or be
   `data:` URIs for images. Remote fonts, remote images and analytics are blocked by the CSP.
4. **Icons carry the class `icon`.** **Glyph SVGs carry `glyph glyph-<name>`.** The layout rules attach to these class
   names.
5. **Avoid `id` attributes inside SVG.** Icons, glyphs and the logo appear many times on one page, so ids would
   repeat.
6. **Do not rename the hooks.** The script finds elements by `data-` attributes and classes that `site/build.ts` and
   `src/web/app.ts` own (for example `data-tool`, `data-form`, `data-app`, `.button`, `.output`). A theme styles them
   and does not rename them.
7. **Both color modes and phone widths must work.** Check them before you deploy; a long label, a wide button or a
   missing `min-width: 0` on a flex or grid child can cause horizontal scrolling.
8. **Keep restricted assets out of the public repository.** Fonts under licenses that forbid redistribution belong in a
   private theme folder. `files` can point anywhere on your disk.
